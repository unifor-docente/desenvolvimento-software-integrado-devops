# Checklist de segurança — preencher com evidências

Use **atendido**, **pendente** ou **não aplicável com justificativa**. Não marque como atendido sem verificar. O checklist apoia os critérios existentes e não altera pesos de avaliação.

| Item | Estado | Evidência ou justificativa | Responsável / prazo |
|---|---|---|---|
| Segredos reais fora do código, imagem, logs e prompts | | | |
| Configuração e destino revisados antes da promoção | | | |
| Permissões do job/serviço limitadas ao necessário | | | |
| Dependências e base avaliadas com ferramenta pertinente | | | |
| Achados de segurança tratados ou exceção documentada | | | |
| Diff revisado; testes relevantes preservados | | | |
| Operação funcional validada além do healthcheck | | | |
| Referência anterior e compatibilidade de dados verificadas | | | |
| Recuperação acionável e resultado do ensaio identificado | | | |
| Uso de IA revisado e validado quando presente | | | |

## Se houver exceção

Descreva risco e exposição, motivo da exceção, medida compensatória, responsável pela decisão, validade/prazo e teste ou revisão para encerrá-la. Desativar um scan sem esse registro não documenta aceitação de risco.
